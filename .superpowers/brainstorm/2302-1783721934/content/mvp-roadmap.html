🗺️ MVP 迭代路线图

6 个阶段，目标：6-8周 跑通第一个工作流

1

Phase 1: 基础设施（Week 1-2）

FastAPI 脚手架 · SQLAlchemy 模型 · Alembic 迁移 · JWT 认证 · 多租户中间件 · Docker Compose · CI 流水线

🎯 里程碑：docker-compose up 能启动 + 注册登录
2

Phase 2: 工作流引擎核心（Week 2-3）

DAG 解析 + 拓扑排序 · 节点注册表 · 执行上下文 · 同步执行引擎 · 基础节点（Input/LLM/Template/Output） · SSE 推送

🎯 里程碑：API 触发线性工作流执行成功
3

Phase 3: 前端画布（Week 3-4）

React + React Flow 集成 · 节点调色板（拖拽到画布） · 自定义节点组件 · 边连接 · 节点配置面板 · 工作流 CRUD UI

🎯 里程碑：画布上拖拽出工作流 → 保存 → 加载
4

Phase 4: 完整执行闭环（Week 4-5）

画布 → 保存 → 触发执行 → SSE 实时状态 → 结果展示 · 控制流节点（If-Else/迭代/人工输入） · 数据处理节点（代码/HTTP/文档提取） · 变量聚合

🎯 里程碑：完整工作流拖拽→执行→结果的闭环
5

Phase 5: 知识库 + RAG（Week 5-6）

文档上传 → 解析（PDF/DOCX/TXT） → 分块 → Embedding → pgvector存储 → 混合检索 · 知识库管理 UI · 知识检索节点

🎯 里程碑：上传文档→工作流中检索→LLM回答
6

Phase 6: Agent + 场景接入（Week 6-8）

Agent 节点（工具调用） · 你的已有场景智能体适配 · Chatflow 多轮对话 · 工作流模板/市场 · 运行历史与监控

🎯 里程碑：Agent 节点调用已有场景智能体

⚠️ 重要提醒：TDD 模式

根据 CLAUDE.md 和 LOOP.md 的要求，每个阶段都必须严格执行：

  • 测试先行 — 先写测试 → 失败 → 实现 → 通过 → 重构
  • 小步提交 — 每个任务 ≤ 30分钟
  • 覆盖率目标 — 单元测试 ≥ 80%，核心业务 ≥ 95%
  • 自动验证 — lint → unit test → integration test → build

意味着实际时间会比上述估算长，但质量有保障。
